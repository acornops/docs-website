This page covers deployment-level automation controls. For authoring and using automation, see [Agents and Workflows](/use/agents-and-workflows).

## Workflow dispatch

Workflow dispatch is enabled by default after startup. Complete required
migrations before starting the control plane. Workspace readiness,
authorization, approvals, target compatibility, and integration checks still
apply to every run.

Use the existing workspace execution controls for maintenance:

| Environment variable | Helm value | Effect when false |
| --- | --- | --- |
| `WORKSPACE_ADMISSION_ENABLED` | `workspaceCapacity.admissionEnabled` | Reject new execution admissions while accepted work drains. |
| `WORKSPACE_DISPATCH_ENABLED` | `workspaceCapacity.dispatchEnabled` | Pause dispatch of accepted work, subject to its queue deadline. |

Both default to `true` and apply across workspace execution types. A dispatch
pause does not stop already-running work. Set both to `false` when maintenance
requires pausing both new admissions and dispatch. Review pending work before
reopening dispatch.

Set `AUTOMATION_WORKER_INTERVAL_MS` or Helm `automation.workerIntervalMs` to
change the worker poll interval, which defaults to 1000 milliseconds.

## Remove retired rollout settings

Use these settings with a control-plane image that removes the rollout mode.
Do not remove rollout settings from an older binary that still defaults to
disabled dispatch.

Remove `AUTOMATION_RUNTIME_MODE` and `AUTOMATION_CANARY_WORKSPACE_IDS` from your
environment files. New binaries do not read these variables, so an old `off`
value no longer pauses work. Replace an intentional pause with the workspace
controls before upgrading.

Remove `automation.runtimeMode` and `automation.canaryWorkspaceIds` from Helm
overrides. The chart rejects these retired properties. Supply a cleaned values
file that preserves your other overrides instead of using `--reuse-values`.

## Runtime and retention

Workflow execution duration and report retention are deployment policies:

| Helm value | Environment variable | Purpose |
| --- | --- | --- |
| `agent.runtime.maxRuntimeMs` | `AGENT_MAX_RUNTIME_MS` | Maximum Workflow and target-chat execution duration |
| `components.controlPlane.reportArtifacts.maxRetentionDays` | `GENERATED_DOCUMENT_RETENTION_DAYS` | Retention for generated documents |

Workflow definitions cannot increase these limits.

## Diagnostics

Authorized workspace readers can inspect the automation diagnostics endpoint for admission and dispatch availability, pending dispatch age, run counts, scheduler lag, pending approvals, template readiness, and retained report-source counts.

Diagnostics expose `runtime.admissionEnabled` and `runtime.dispatchEnabled`.
Update clients that read the retired `runtime.mode` and
`runtime.workspaceEnabled` fields. An admission-only pause lets accepted work
drain; diagnostics report `disabled` when dispatch is paused.

Monitor the control-plane automation metrics and supplied Prometheus alert rules. Alert on delayed dispatch, scheduler lag, stale approvals, review-blocked runs, trigger rejection, MCP readiness failures, cleanup retries, report failures, and elevated terminal failures.

Diagnostics and metrics must contain bounded IDs, states, counts, and reasons only. Do not export prompts, chat bodies, tool arguments, webhook payloads, reports, credentials, or continuation state.
